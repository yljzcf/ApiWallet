## 全量代码审查后的安全修复

目标：检查 009 Chrome 扩展现有实现中是否有错误或疏漏，并修复已确认的高风险问题。

### 问题与根因

- `site-config.public.json` 仍保留真实站点配置和鉴权 header 值，包括 JWT、Bearer token、`new-api-user` 数字值；这与此前“公开配置脱敏 / 空白初始态”的发布目标冲突。
- `popup.js` 和 `add-site.js` 部分 UI 渲染通过 `innerHTML` 拼接来自站点配置的数据，例如站点名、字段路径、编组标题；这些数据可通过导入配置进入 storage，存在扩展页面 DOM 注入风险。

### 改动清单

- 清空 `site-config.public.json`，保留公开发布安全的空数组模板。
- 改造 `popup.js`：
  - `createBaseCardElement()` 改用 DOM API 创建卡片按钮与主体结构。
  - `renderSingleCard()` 改用 `createElement()` / `textContent` 渲染站点名和值节点。
  - `renderGroupCard()` 改用 `createElement()` / `textContent` / `dataset` 渲染编组标题、总值、子站点名和值节点。
- 改造 `add-site.js`：
  - `renderManagedSiteList()` 改用 `createElement()` / `textContent` 渲染站点名与字段路径。
- 更新测试：
  - `task-popup-ui.test.js` 增加公开配置敏感值检查，以及 popup 卡片渲染不得通过 `innerHTML` 拼接站点数据的断言。
  - `task-add-site-ui.test.js` 增加站点列表渲染不得通过 `innerHTML` 拼接站点数据的断言。

- `node --check "/e/vscode/009_chromeExt/popup.js"`

## 单张卡片配置页公式实时预览修复

目标：修复用户反馈的单张卡片配置页中“输入公式后实时预览区没有变化，强行保存后甚至影响原值抓取”的问题。

### 根因

- 单卡编辑页的公式预览依赖 `siteManager.lastPreview.rawValue`。
- 该值只有点击“测试配置”后才会写入；直接打开单张卡片并输入公式时，编辑页没有把当前卡片已有值作为预览基准，因此实时预览保持 `--`。
- 保存时只应落盘公式配置，不能把公式结果当作接口原值。问题本质是“预览原值”和“接口测试原值”的数据流没有分清：打开卡片时缺少预览种子值，测试配置时又必须重新以接口返回原值为准。

### 改动清单

- 改造 [add-site.js](../add-site.js)：
  - `buildDraftCards()` 在单卡草稿中携带当前 `boardData` 展示值。
  - 新增 `siteManager.seedPreview()`，用于打开单卡配置页时用当前卡片值初始化实时预览。
  - `openSiteEdit()` 在进入单卡配置页时，如果存在当前卡片值，立即计算并展示公式预览。
  - 保持“测试配置”路径仍从接口重新抓取原值，公式只影响预览值和保存后的展示公式，不写回 `boardData` 原值缓存。
- 更新 [task-add-site-flow.test.js](../task-add-site-flow.test.js)：
  - 新增回归用例：打开单卡配置页后直接输入 `A/500000`，应立即把已有卡片值 `5039770.00` 预览为 `10.08`。
  - 断言保存公式不改写 `boardData`。
  - 断言保存后重新测试配置仍显示接口原值，并只在预览区应用公式。

### 回归结果

已通过：

- `node "/e/vscode/009_chromeExt/task-add-site-flow.test.js"`
- `for f in /e/vscode/009_chromeExt/task-*.test.js; do node "$f" || exit 1; done`
- `node --check "/e/vscode/009_chromeExt/add-site.js"`
- `node --check "/e/vscode/009_chromeExt/popup.js"`
- `node --check "/e/vscode/009_chromeExt/site-config-shared.js"`

### 简短复盘

- 值得保留：这类问题要沿着“打开卡片 → 输入公式 → 预览 → 保存 → 重新测试”的完整数据流定位，不能只看公式计算函数本身。
- 可以优化：编辑页现在同时支持“当前卡片值预览”和“接口测试原值预览”，后续 UI 可考虑在文案上区分“当前缓存值预览”和“重新测试原值”，减少用户误解。

## 单站点配置页重设计与公式功能恢复

目标：按用户草图重新设计 009 Chrome 扩展的单站点配置页面，并恢复“接口原值 → 可选公式计算 → 面板输出”的高级配置能力。

### 已确认设计

- 新增站点和编辑站点统一使用同一个现代卡片式配置页面。
- 顶部提供“返回面板”和“删除站点”；删除站点仅编辑已有站点时可用。
- 基础配置包含站点名、接口地址、监控字段、鉴权字段下拉框和鉴权字段值。
- 原值行采用方案 B：`访问接口，获取原值`、原值展示、`完成配置` 同行。
- 高级设置默认收起，展开后显示公式输入、测试计算按钮和计算结果展示。

### 关键交互规则

- 点击“访问接口，获取原值”只请求接口并更新原值展示，不自动计算公式。
- 公式输入框失焦时不再触发重新预览，不会清空公式或原值。
- 点击“测试计算”只读取当前原值和当前公式计算，不重新请求接口。
- 公式为空时允许完成配置，面板显示原值。
- 公式非空时必须先测试计算通过，才允许完成配置。
- popup 运行时公式错误显示“公式错误”，不覆盖上一次成功的 `boardData`。

### 改动清单

- 改造 [site-config-shared.js](../site-config-shared.js)：
  - 新增 `calculationExpression` 配置字段。
  - 新增安全四则运算解析与计算函数，支持 `X`、数字、小数、括号、`+ - * /`，不使用 `eval` / `new Function`。
  - `normalizeSiteConfigs()` / `serializeSiteConfigs()` 保留新字段并继续丢弃旧 `formula` / `divideBy`。
- 改造 [add-site.html](../add-site.html)：
  - 将新增/编辑两套表单整合为统一单站点配置卡片。
  - 添加鉴权字段下拉、原值展示行、高级设置折叠区、公式输入与计算结果展示。
- 改造 [add-site.js](../add-site.js)：
  - 接入统一配置页 DOM 与状态流。
  - 用 `lastRawValue` / `lastTestedExpression` / `lastCalculatedValue` 分离原值、公式和计算结果。
  - 修复公式输入框失焦清空公式与原值的严重问题。
- 改造 [popup.js](../popup.js)：
  - 运行态通过 `calculationExpression` 输出面板值。
  - 公式错误时显示“公式错误”且不覆盖旧值。
- 更新测试：
  - [task-formula-calculation.test.js](../task-formula-calculation.test.js)
  - [task-add-site-ui.test.js](../task-add-site-ui.test.js)
